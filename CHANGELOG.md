# Changelog

All notable changes to openre are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.2.0] - 2026-10-21

The villa renovation: the same platform, rebuilt around its real engines,
with the presentation it deserved.

### Added

- The CLI is whole: all ten subcommands (`hunt`, `scan`, `analyze`, `ai`,
  `exploit`, `remediate`, `report`, `config`, `queue`, `schedule`) wired to
  the real workspace crates, replacing three hand-copied stub modules. The
  binary is named `openre`. `analyze` drives openre-analysis's extractors
  and openre-disasm's capstone disassembly (info, symbols, imports,
  exports, sections, functions, ranges, and the staged pipeline); `ai`
  talks to openre-ai's AiService built from real config; `remediate`
  consults the KnowledgeBase and VerificationEngine; `queue` runs on a
  local SQLite job store with submit/status/logs/cancel/retry/stats.
- `openre completions <bash|zsh|fish|powershell>` via clap_complete.
- A 17-artifact release pipeline (`.github/workflows/release.yml` +
  `scripts/package_release.py`): Linux (x86-64 glibc/musl/i686, aarch64
  glibc/musl, armv7, armv6, riscv64, loongarch64, powerpc64le, s390x),
  Windows (MSVC + GNU x86-64/i686 + arm64), macOS (aarch64, x86_64, and a
  universal2 fat binary), and FreeBSD x86-64. Every archive carries the
  three binaries plus shell completions, staged deterministically, with
  per-archive sha256 and a combined checksums file. Cross-compilation
  vendors OpenSSL through zig; zig is pinned to the version the matrix was
  verified against.
- CI runs the test suite on Linux, Windows, and macOS; clippy gates at
  `-D warnings` across every crate (the cli/tui exclusions are gone).
- Dependabot (cargo + github-actions), release-notes categories, and a
  funding file.
- A visual identity: lavender on `#0D0E12`/`#FBFBFC` with three accent
  modes (EXPLOIT crimson, RECON amber, DEFEND slate green) that never
  share a screen — vector logo that adapts dark/light by itself, social
  preview, mode banners, and an animated scan demo, all generated by
  committed deterministic scripts.
- docs/ restructured: the product-management binder moved to
  `docs/archive/`, an engineer's handbook written in its place
  (architecture, cli, checks, ai-providers, sarif, PERFORMANCE).

### Changed

- Release profile tuned and measured: fat LTO, one codegen unit, symbols
  stripped, tokio's feature set trimmed from `full` to the 8 features the
  code exercises — total binary size −20.6% (`docs/PERFORMANCE.md`).
- The scan integration fixture (`test_server.py`) lives next to the tests
  that spawn it; all 12 pass.

### Fixed

- Five malformed SQL placeholders (`&N` → `?N`) in openre-storage's
  history layer, which broke `openre report create`.
- schedule.rs compiles for the first time since its refactor (typed
  rusqlite reads, `.optional()` queries, a duplicated block removed).
- openre-tui: 82 clippy warnings → 0 under `-D warnings --all-features`,
  with real fixes (oversized event payloads boxed, match guards, dead
  code removed) rather than lint suppressions.

## [0.1.0] - 2025

Initial public release: web/API security scanning with 18 checks across
three profiles, binary analysis for ELF/PE/Mach-O/WASM with CFG/DFG
recovery, a local-first AI research layer, PoC exploit generation,
remediation guidance, SARIF output, a ten-panel TUI, and a plugin
system.
